# SP-9 — Canonical Structure Graph (JSON, Neo4j deferred) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build a typed node/edge graph (`CONTAINS` + `READING_ORDER`) from the SP-8 AST via a pure
`build_graph` + a `GraphStage` (`deps=("ast",)`) that auto-chains off `ast`, emitting a versioned JSON
artifact. **Neo4j loading is explicitly out of scope this slice** — no new container, no `graph`
Compose profile, no loader.

**Architecture:** `GraphStage` reads the AST (`ctx.read("ast")`), returns
`{schema_version, nodes[{id,type,label}], edges[{source,target,type}]}` — one `document` node, one
`section` node per AST section, one `paragraph` node per paragraph; `CONTAINS` edges document→section
and section→paragraph; `READING_ORDER` edges between consecutive sections and between consecutive
paragraphs within a section. Reuses SP-2's derived-stage machinery; no framework change.

**Tech Stack:** Python 3.13, the SP-2 framework, pytest + testcontainers, `uv`. Design:
`docs/superpowers/specs/2026-07-17-sp9-graph-design.md`.

## Global Constraints

- `uv run --directory backend <cmd>` — NEVER `uv --project`.
- Import contract `api | workers → pipeline → platform → core`, `exhaustive`. `core` pure —
  `fdi/core/graph.py` no I/O. `GraphStage` lives in `pipeline`.
- `mypy --strict`: use `isinstance` narrowing (mirror `fdi/core/ast.py`'s defensive style) when reading
  `object`-typed values out of the AST `Mapping`; no blanket `# type: ignore`. `cast` only where
  `isinstance` alone can't satisfy the checker (e.g. narrowing `ctx.read("ast")`'s `object` return to
  `Mapping[str, object]` before calling `build_graph`, same as `AstStage`/`QualityStage` already do).
- Determinism: `build_graph` is a pure function of the AST — no RNG/clock/UUIDs; node ids are
  positional (`"doc"`, `"s{i}"`, `"s{i}p{j}"`).
- On Windows prefix `lint-imports` with `PYTHONUTF8=1`.
- Integration: reuse `session_factory` + `store` fixtures; unique ids per test; **LOCAL**
  `StageRegistry` (register `OcrStage`+`NormalizeStage`+`AstStage`+`GraphStage`, not the global
  `REGISTRY`).

# backend/src/fdi/pipeline/stages/graph.py
"""GraphStage: a DERIVED stage that builds the typed CONTAINS/READING_ORDER
graph from the naive AST. Auto-chains off AstStage via `deps=("ast",)`."""

from collections.abc import Mapping
from typing import cast

from fdi.core.graph import build_graph
from fdi.pipeline.registry import REGISTRY
from fdi.pipeline.stage import StageContext


class GraphStage:
    name = "graph"
    version = 1
    deps: tuple[str, ...] = ("ast",)

    async def run(self, ctx: StageContext) -> object:
        ast = await ctx.read("ast")
        return build_graph(cast(Mapping[str, object], ast))


REGISTRY.register(GraphStage())

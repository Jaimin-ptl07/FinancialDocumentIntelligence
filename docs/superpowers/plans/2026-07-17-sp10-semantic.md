# SP-10 — Semantic Intelligence via Azure OpenAI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Classify each SP-8 AST section into one of 8 financial-statement types by running Azure OpenAI
(GPT) as a derived pipeline stage — proven end to end with a FAKE LLM client (no live Azure OpenAI), plus
an opt-in real smoke test.

**Architecture:** A `SemanticStage` (SP-2 derived stage, `deps=("ast",)`) reads the AST artifact via the
already-existing `ctx.read("ast")`, calls an injected `SemanticClient` (fake in tests, `AzureOpenAIClient`
in prod) per section, and returns `{schema_version:1, sections:[{heading, type, paragraph_count}]}`.
Content-addressed on `derived_input_hash([ast.output_hash])` + `SemanticStage.version` — this caching is
**already generic** in SP-2's `run_stage` (no framework change, unlike SP-5's OCR root-stage work); GPT
output is non-deterministic so "run once, cache" is deliberate.

**Tech Stack:** Python 3.13, `openai` (official SDK, `AzureOpenAI` client), FastAPI, Celery, SQLAlchemy,
MinIO, Postgres, pytest + testcontainers, `uv`. Design: `docs/superpowers/specs/2026-07-17-sp10-semantic-design.md`.

## Global Constraints

- `uv run --directory backend <cmd>` — NEVER `uv --project`.
- Import contract `api | workers → pipeline → platform → core`, `exhaustive`. `core` pure (`SectionType` +
  `build_snippet` have no SDK import). The `AzureOpenAIClient` (does I/O) lives in `platform`. The
  `SemanticClient` protocol + `SemanticStage` + `FakeSemanticClient` live in `pipeline`.
- **Do not break SP-2/SP-5/SP-8:** `StageContext`/`run_stage` are used AS-IS — no signature changes.
  Existing ping/ocr/normalize/ast tests keep passing untouched.
- Determinism exception: semantic artifacts are content-addressed on `derived_input_hash([ast.output_hash])`
  + `SemanticStage.version` (GPT is non-deterministic). A second `semantic` run on the same doc is a store
  cache hit that does NOT call Azure OpenAI — prove it with a call counter on the fake.
- **No live Azure OpenAI in the suite:** all unit/integration tests use `FakeSemanticClient`. The
  real-Azure-OpenAI test is `@pytest.mark.azure` (the SAME marker SP-5 registered for Document
  Intelligence — broadened here to cover any live Azure service), skipped unless `FDI_GPT_ENDPOINT`/
  `FDI_GPT_KEY` are set.
- Any new `FDI_` field → Settings AND compose `x-backend-env` AND `.env.example` (inert-config lesson).
  `FDI_GPT_ENDPOINT`/`FDI_GPT_KEY` are `str | None = None` so empty→None boots cleanly.
- Integration tests: reuse `session_factory` + `store` fixtures; mint unique ids/checksums per test
  (session-scoped DB).
- On Windows prefix `lint-imports` with `PYTHONUTF8=1`.

**Canonical commands:** fast `pytest -m "not integration and not e2e and not azure" -q`; integration
`pytest tests/integration -q`; gates `ruff check .` · `mypy --strict src` ·
`PYTHONUTF8=1 lint-imports --config .importlinter`.
